PROJECT — PANEL TRANSPARENCY TOGGLE

A widget whose whole job is its own panel —
except nothing hands it a reference to one.

A small Plasma 6 applet: drop it in your panel and it makes the panel translucent, at whatever opacity you want, with an option to hide the widget itself once you're done arranging it. The interesting part is what it has to do just to reach the panel it's sitting in — Plasma doesn't hand an applet its own containment, so this one goes looking for it.

what it is

A rewrite, said plainly

The README doesn't dress this up as something original: it's Panel Transparency Button by psifidotos, ported for Plasma 6. When Plasma 6 shipped, its applet API changed enough that older Plasma 5 widgets like the original stopped loading, and this is a from-scratch QML rewrite that keeps the same idea — a panel widget that toggles background transparency — while adapting to the new declarativeappletscript API and adding a few things the original didn't have: an opacity slider instead of a flat on/off, and a context menu alongside the button itself.

why

The applet you actually use every day breaking is motivating

This is the kind of small utility that only gets written because its absence is annoying on your own desktop, every day, immediately after an upgrade. Plasma 6 didn't remove the ability to make panels translucent — it removed the specific old applet that did it. Porting a working QML rewrite is a smaller task than it sounds like from outside, and also a good way to actually learn the new applet API instead of reading about it.

main.qml · lookForContainer

An applet doesn't get a reference to its own panel

To disable a panel's background or change its opacity, this widget needs a handle to the containment — the panel itself, as a QML object — not just to itself. Plasma's public API doesn't hand that over directly to an applet.

function lookForContainer( object , tries ) {
    if ( tries == 0 || object == null ) return ;
    if ( object.toString().indexOf("ContainmentItem_QML") > -1 ) {
        root.containmentItem = object ;
    } else {
        lookForContainer( object.parent , tries-1 ) ;
    }
}

The workaround is to walk up the QML parent chain from the applet's own item, checking each ancestor's default toString() — which for a QML object includes its underlying C++ class name — for the substring "ContainmentItem_QML". That string is an internal implementation detail of Plasma, not a documented API, which is exactly why it has to be found this way instead of asked for directly. The walk is capped at 14 hops so a lookup that will never succeed doesn't recurse forever.

main.qml · initializeAppletTimer

The panel might not exist yet when the applet does

At Plasma startup, this applet's QML can finish loading before its containment is fully constructed — so the very first lookForContainer call can legitimately fail through no fault of the walk itself. Rather than fail once and stay wrong until the user clicks something, a Timer retries every 1200ms, up to four extra attempts, logging which attempt actually found the containment. It's a small, honest acknowledgment that "run once at startup" isn't reliable in a plasmoid's actual load order, and the fix is patience rather than a cleverer lookup.

what's actually rough

Where a private API bites back

◐ known fragility

Matching an internal class name in toString() is exactly the kind of thing a future Plasma release can quietly rename, at which point this applet stops finding its containment with no compile-time warning — it'll just silently fail to disable the background.

◐ credited, not hidden

This project's value is the port and the Plasma-6-era additions (opacity slider, context menu) — not the original idea, which the README attributes to psifidotos's Plasma 5 applet up front.

✓ landed

The retry timer turned an intermittent "works on the second panel but not the first one loaded" bug into something that just quietly works within a couple seconds of login, every time.

if this gets picked back up

What's next

  • A more resilient containment lookup that doesn't depend on one specific internal class name string, if Plasma ever exposes a public way to do this.
  • Per-panel opacity, for anyone running more than one panel with different intentions for each.
  • Publishing to the KDE Store so it's installable without cloning the repo by hand.
