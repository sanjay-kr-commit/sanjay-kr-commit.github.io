A build system for my zsh environment.

I wanted my shell configuration to behave less like a growing .zshrc and more like a project.

GitHubProject pageDetails

Why it exists

I had a shell configuration that kept growing. At some point, adding another function stopped feeling free.

Ordering needed dependencies. Rebuilding needed change detection, which led to fingerprints. Generated state needed safe replacement, which led to snapshots. Startup time made lazy loading worth having. I did not set out to write a framework. Each question produced one more small piece, and together they became a build system. It is still just zsh underneath.

How it works

Modules stay ordinary zsh files. Comments in them describe priorities, dependencies and flags. ZForge builds a snapshot from them and zsh starts from that.

module source
  ↓
metadata
  ↓
fingerprint
  ↓
validate + order
  ↓
generate
  ↓
snapshot
  ↓
zsh

On a warm start the existing snapshot loads immediately while ZForge checks in the background whether anything changed. If it did, the new snapshot is prepared separately and used by the next shell. If it did not, the snapshot is reused. A cold start, with no snapshot yet, generates one first.

If generation fails, the previous snapshot stays in place and the failed fingerprint is recorded, so a broken configuration is not rebuilt in every shell.

A module is still zsh

#!/bin/env zsh

# @p -> 50
# @d -> tmux_terminal
# @f -> MY_FEATURE

my_feature() {
    ...
}

The comments set priority, a dependency and a dynamic flag. The module does not need a second language.

Numbers

Warm initialization measured about 190 ms in my development configuration, with the relevant module disabled and tmux removed. It is one measurement from one environment, not a benchmark.

The source is 70 files (18 modules, 15 enabled) and 2,826 lines of runtime and module source. That is the size of the source, not what warm startup parses. Startup works from generated state, and fingerprints exist to avoid unnecessary regeneration.

Still evolving

ZForge works, and it is still a personal project. Current work is on generation safety and tests, dependency diagnostics, snapshot tooling and developer tooling, plus some known bugs. Limits and current work, or TODO.md in the repository.
