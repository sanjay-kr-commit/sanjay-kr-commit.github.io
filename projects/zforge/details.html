Details.

The parts worth knowing, and what is not finished.

Fingerprints and snapshots

A SHA-256 hash of the generation-relevant state (module configuration and source, runtime source, dependencies, and boot flags that affect generation) tells ZForge whether the configuration changed. It is for change detection. It does not mean a rebuild on every shell.

Snapshots are indexed by that hash, so returning to an earlier configuration reuses its existing snapshot. Generation writes a candidate separately and publishes it only on success, so an incomplete build never replaces the working runtime. FREEZE_BACKGROUND_VALIDATION turns the background check off, and zforge --generate forces a foreground build.

Module metadata

@p -> NPriority.
@d -> nameDepends on another enabled module. A missing one is rejected, not ignored.
@f -> FLAGRegisters a dynamic flag.
@e -> VARDeclares an environment variable the module uses.
@nomergeKeeps the module out of the merged master file; it is sourced separately.
@lazy, @nolazyRequest or disable lazy handling for the module.

The analyzer checks dependency presence, circular dependencies and priority conflicts. Merged modules are wrapped in an anonymous function so a top-level return stays inside the module.

Lazy generation

A text-based analyzer finds functions that can be replaced with a wrapper that loads the real definition on first call. It is not a zsh parser, so unusual syntax may confuse it. @nolazy is the escape hatch.

Flags

Boot flags live in local/public/runtime/bootflags (for example SILENT_LOG, LOGALL). Runtime flags live in local/public/runtime/flags. Dynamic flags are declared by modules with @f. The :flags command manages all three. :log shows the session log, and EMBED_FILE_ID_FOR_DEBUG embeds module identifiers in generated output.

Public and private state

Configuration is split into local/public/ and local/private/. The gocryptfs module handles encrypted private configuration. Once it is mounted and decrypted, the content is available to the local environment like any other files.

Limits

  • Linux and zsh only. It relies on /dev/shm, grep -P, realpath, find and GNU-style tools. macOS compatibility has not been established.
  • The lazy analyzer works on text. The generated-script syntax check is currently stubbed.
  • There is no resource-conflict model between modules yet.
  • External tools (fzf, uuidgen, tmux, zoxide, gocryptfs, jq, htmlq, fastfetch and others) are not yet declared or diagnosed per module.
  • gitPass still handles tokens in plaintext. Replacing that with a credential helper is on the TODO.
  • Tests for generation, snapshot reuse and lazy wrappers are not written yet.
