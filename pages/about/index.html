About Me

The story behind the repositories.

Who I Am

I'm a software engineer who enjoys understanding software as much as building it. Most of my projects begin with curiosity rather than a product idea. If I encounter an algorithm, desktop feature, file format, or tool that I don't fully understand, my first instinct is usually to explore its implementation.

That curiosity explains why my repositories range from compression algorithms and language interpreters to KDE Plasma customization, Kotlin Multiplatform applications, desktop tooling, and automation scripts.

How I Learn

Reading documentation is usually only the starting point. I like reading source code, experimenting with small prototypes, and implementing simplified versions of ideas before relying on existing libraries.

  • Build first, optimize later.
  • Read source code when documentation leaves questions unanswered.
  • Automate repetitive tasks whenever possible.
  • Document discoveries so future me can revisit them.

Daily Environment

My primary workstation runs Linux with KDE Plasma configured as a tiling desktop using Krohnkite, virtual desktops, and custom KWin effects. Development revolves around Neovim, tmux, Git, Konsole, Obsidian, Zen Browser, and a collection of small scripts that gradually became part of my workflow.

Instead of replacing the desktop environment, I prefer understanding and extending it. That interest naturally led to experimenting with Plasma widgets, KWin, and open source contributions.

Projects That Define Me

  • Tanoshi Multiplatform – exploring Kotlin beyond Android.
  • Dotfiles – evolving my Linux development environment.
  • Huffman Encoding and Deflate – understanding compression.
  • Brainfuck Interpreter and Expression Evaluator – exploring language implementation.
  • Open Source Contributions – contributing to projects I use every day.

Engineering Philosophy

"The most interesting software is often the software beneath the software."

I'm drawn to developer tools, operating systems, build systems, editors, desktop environments, parsers, and algorithms because they shape everything built on top of them. Improving those layers makes everyday development more enjoyable and teaches lessons that transfer across projects.

Beyond Code

Outside of writing software, I enjoy refining the environment in which software is written. My editor, terminal, desktop, notes, and workflow evolve alongside my projects. I see them as part of the engineering process rather than separate from it.

This portfolio reflects that perspective. It documents not only what I have built, but also how I approach problems, learn new concepts, and continuously improve the tools I use every day.
